# ระบบนำเข้าข้อมูลตารางเรียน (xlsx → MySQL)

- **frontend/** Next.js 15 + Tailwind (port 3000)
- **backend/** Bun + Elysia + Drizzle ORM (port 3001)
- **MySQL** ผ่าน Docker Compose หรือ XAMPP

## ติดตั้งครั้งแรก

1. ติดตั้ง Bun: `powershell -c "irm bun.sh/install.ps1 | iex"` (แล้วเปิด terminal ใหม่)
2. เปิด MySQL (เลือกอย่างใดอย่างหนึ่ง)
   - **Docker:** `docker compose up -d` → MySQL :3306, phpMyAdmin http://localhost:8080
   - **XAMPP:** กด Start MySQL แล้วแก้ `backend/.env` เป็น `DB_USER=root` `DB_PASSWORD=` (ว่าง)
3. Backend
   ```
   cd backend
   bun install
   bun run db:setup     # สร้าง database (utf8mb4) + ตาราง
   bun run dev
   ```
4. Frontend (terminal ใหม่)
   ```
   cd frontend
   bun install
   bun run dev
   ```
5. เปิด http://localhost:3000

## ลำดับการนำเข้า
1. กลุ่มเรียน → 2. รหัสวิชา/คาบเรียน → 3. อาจารย์/วิชาที่สอน → 4. อาคารเรียน

นำเข้าซ้ำได้: ระบบ upsert ตาม key (รหัสกลุ่ม, รหัสวิชา, ชื่ออาจารย์, ชื่ออาคาร)

## จัดตารางสอนอัตโนมัติ (หน้า /schedule)
- จันทร์–ศุกร์ วันละ 10 คาบ, ยึด "กลุ่มเรียน × รายวิชา × ชั่วโมง" เป็นหลัก แล้วเติมอาจารย์ (ผู้สอนหลักก่อน → ภาระน้อยสุด) และอาคาร
- ไม่มีอาจารย์ว่าง → แสดง "รอจัดสรรอาจารย์"
- อาคาร: วิชาสามัญ (20000/30000-1xxx) → อาคารสามัญศึกษา, วิชาอื่น → อาคารของประเภทวิชาจากรหัสกลุ่ม (01 อุตสาหกรรม, 02 บริหารธุรกิจ, 09/19/21 เทคโนโลยี, อื่น ๆ อาคารเรียนรวม)
- ตรวจผลซ้ำทุกเงื่อนไขบังคับด้วยตัวตรวจแยก (`src/schedule/validate.ts`) + DB unique key กันกลุ่ม/อาจารย์ชนคาบ
- ส่งออก CSV (เปิดใน Excel ได้), พิมพ์ได้

| Method | Path | |
|---|---|---|
| POST | `/api/schedule/generate` | `{ activityMode: "period10" \| "groupLast" }` |
| GET | `/api/schedule/runs` / `/runs/:id` / `/runs/latest` | ผลการจัด + รายงาน |
| GET | `/api/schedule/runs/:id/keys?by=group\|teacher\|building` | รายการให้เลือก |
| GET | `/api/schedule/runs/:id/grid?by=…&key=…` | ตาราง |
| GET | `/api/schedule/runs/:id/export.csv` | ส่งออก |

โค้ดหลัก: `backend/src/schedule/` (solver.ts = อัลกอริทึม, validate.ts = ตัวตรวจ, rules.ts = กฎอาคาร/วิชาพิเศษ)

หมายเหตุ: `bun run db:setup` ใช้ SQL `CREATE TABLE IF NOT EXISTS` (ไม่ใช้ drizzle-kit push เพราะ crash กับ MariaDB ของ XAMPP) รันซ้ำได้ ไม่ลบข้อมูล

## จัดการข้อมูลเอง (หน้า /manage/…)
- เพิ่ม/แก้ไข/ลบ: กลุ่มเรียน, รายวิชา, วิชาของกลุ่ม, อาจารย์, อาจารย์–วิชาที่สอน, อาคาร, ห้องเรียน
- ตรวจเหมือนตอนนำเข้า: ตัดช่องว่างในรหัส, ฟิลด์บังคับ, ตัวเลข/ช่วงค่า, ค่าที่เลือกได้, ข้อมูลอ้างอิงต้องมีอยู่จริง, ห้ามซ้ำ, ชั่วโมงรวมของกลุ่ม ≤ 40 คาบ/สัปดาห์
- ลบแล้วลบข้อมูลที่ผูกกัน (cascade) — หน้าเว็บแจ้งก่อนลบ
- API: `GET/POST /api/manage/:entity`, `PUT/DELETE /api/manage/:entity/:id`, `GET /api/manage/meta`, `GET /api/manage/:entity/options`

## เวลาไม่ว่างของอาจารย์ (หน้า /availability)
- คลิก/ลากเลือกคาบที่ไม่ว่าง → ตัวจัดตารางไม่จัดสอนในคาบนั้น (เงื่อนไขบังคับข้อ 2)
- API: `GET/PUT /api/manage/teachers/:id/unavailable` (`{ slots: ["วัน:คาบ", …] }`, 0-based)

## จัดระดับห้อง
- อาคารที่มีห้องลงทะเบียน → ทุกคาบต้องได้ห้อง: อยู่อาคารเดียวกัน, ประเภทตรง (บรรยาย/ปฏิบัติการ), ความจุ ≥ จำนวนนักศึกษา (ไม่ระบุ = 30), ไม่ชนห้อง
- วิชาที่ไม่ต้องใช้ห้องปฏิบัติการจะใช้ห้องแล็บเป็นลำดับสุดท้าย (เก็บแล็บไว้ให้วิชาปฏิบัติ)
- อาคารที่ไม่มีห้อง → จัดระดับอาคารเหมือนเดิม; กิจกรรมองค์การวิชาชีพ จัดระดับอาคารเสมอ (ทุกกลุ่มพร้อมกัน)
- ห้องไม่พอ/ไม่มีห้องที่เหมาะ → แจ้งในรายงาน "จัดไม่ครบ" พร้อมเหตุผล (ไม่ยอมให้ห้องชน)
- นำเข้าจาก Excel ได้: ไฟล์อาคารใส่คอลัมน์ `ห้องเรียน`, `ความจุ`, `ประเภทห้อง`; ไฟล์กลุ่มเรียนใส่คอลัมน์ `จำนวนนักศึกษา`

## ใช้เฉพาะข้อมูลที่ใช้ได้จริง
- งานที่ต้องจัด = รายการลงทะเบียน (กลุ่มเรียน × รหัสวิชา × คาบ) เท่านั้น
- ผู้สอน = อาจารย์ที่สอน **รหัสวิชาเดียวกับที่กลุ่มลงทะเบียน** (ไม่ดูแผนกของอาจารย์)
- วิชาที่ไม่มีกลุ่มลงทะเบียน และรายการสอนของวิชานั้น → ไม่นำมาประมวล แค่นับแจ้ง
- แผนก → อาคาร: แผนกของกลุ่มดูจากรหัสกลุ่มหลักที่ 4–5 (01 อุตสาหกรรม, 02 บริหารธุรกิจ, 04/15 คหกรรม, 07 ท่องเที่ยวและโรงแรม, 09/19/21 เทคโนโลยีสารสนเทศ), วิชาสามัญ → แผนกสามัญ; จับคู่กับชื่ออาคาร (เช่น "อาคารคหกรรม") ถ้าไม่มีอาคารของแผนก → อาคารเรียนรวม
